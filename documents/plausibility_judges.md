# Plausibility/self-assessment judges for Architect + Planner (RESUME DOC)

**Goal (user-approved):** add two ADVISORY judges, symmetric to the Analyst's `analyst_sense_judge`:
1. **Architect design-plausibility judge** — does each aspect's design (components/functions/interfaces) coherently REALIZE its requirements? Catch OMISSION (a required capability no element covers), DRIFT (an element that matches no requirement), OUT-OF-DOMAIN (a build/design tool as a product element — the "Architect Agent shall…" class).
2. **Planner plan-plausibility/completeness judge** — do the tasks traced to a requirement TOGETHER fully realize it (complete) without fabricating/drifting (plausible)?

**Hard constraints (lessons this session):**
- Both are **ADVISORY**, surfaced for human review — NOT hard release/handoff gates. LLM judges start weak.
- **Battery-test each BEFORE wiring** (a discrimination battery of must-flag + must-not-flag cases, like the sense judge's 10/10). Iterate the prompt until it discriminates.
- Deploy pattern (mirror sense judge): source prompt is a Python constant in a module; register in agent_server. HOST cannot `import` the agent pkg (no httpx) → register FROM the container: `docker exec <container> python -c "from <pkg> import <mod>; PUT <mod>.PROMPT to http://localhost:7701/admin/api/agents/<name>"`. Params: temp 0, max_tokens ~800, top_p 0.9, chat_template_kwargs.enable_thinking False, memory_policy none.
- temp=0 on judges. Fail OPEN (plausible/complete=true) on malformed model output — a judge error must never condemn.

Battery pattern: `docker exec analyst-agent python` posting to `/v1/chat/completions` with model=<judge>, response_format json_object, per case print flag/ok, assert N/N.
